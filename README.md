## 一、一句话结论

这类海报**不是"设计排版"出来的，是一张被甩糊的风景照 + 一层手写字**。

背景是**真实风景**，被**横向甩镜头（ICM / panning）**拉到看不出细节，只留下"天 / 中景暗带 / 主体"三层色块和方向性拉丝。文字负责信息（手写体、逐行错落、每行字号字距都不同），装饰只留极细的刊头与落款，全画面只有 **1 个撞色**。

"抽象感"来自甩糊，**不来自内容**——所以底图要找的是 `草原`/`麦田`/`夜景天际线`，不是 `抽象背景`。

## 三、复刻流程（A 路线，现在只走这条）

早期试过纯 CSS/SVG 画色块，失败：颜色被旋转挤掉、亮部叠深色必发灰、条纹规整得像矢量图。
现在的做法是**先生成一张真照片，再自己糊**——模型负责"有景"，SVG 负责"糊得对"。

```
① 生图出底图（必须有上/中/下三层）
        ↓
② feColorMatrix 预饱和
        ↓
③ feGaussianBlur 各向异性拉丝（stdDeviation="62 4"）
        ↓
④ CSS filter 调色
        ↓
⑤ 手写体逐行定位
```

### ① 底图：先有"景"，再谈跨度

**这是最容易被忽略、也最致命的一步。** 底图必须有三层：

| 层 | 作用 |
|---|---|
| 上：天空 / 暗背景 | 提供亮极或暗极 |
| 中：暗而略饱和的远带（山影、城际线、树林） | **提供纵深，别漏这层** |
| 下：主体（草坡、麦田、水面倒影） | 提供主色面积 |

一层纹理填满整幅（满屏花、满屏叶、满屏墙）→ 糊完是一整块色斑，**跨度再高也丑**。

**8px 缩略图测试**：缩到 8px 宽还看得出三条带，才能用。

### ② 预饱和

模糊是平均运算，平均必掉彩度。糊之前先提：

```svg
<feColorMatrix type="saturate" values="1.20" result="sat"/>
<feGaussianBlur in="sat" stdDeviation="62 4"/>
```

系数按底图色混程度调：薰衣草 1.55、茶园 1.35、雪原 1.30、草原 1.10、樱花 1.02、麦黄 1.02、黑金 1.18。

### ③ 拉丝方向

```svg
stdDeviation="62 4"   <!-- 横向拉丝 -->
stdDeviation="4 62"   <!-- 竖向拉丝 -->
```

**方向交给 `stdDeviation`，旋转只负责"地平线歪多少度"。** 两件事别合并——用 `rotate(-72)` 做竖拉丝会把地平线一起转成 72°。

拉丝方向要**平行于分层边界**（横向分层配横拉丝），否则三层被撕成条形码。

**半径按场景密度定**：开阔风景 62~95，密市场景 30~46。

### ④ 调色：别用 brightness 救暗部

```css
.bg { filter: saturate(1.10) contrast(1.08) brightness(1.04); }
```

`brightness` 拉过 1.2，黑就变棕——"黑金"直接变"棕金"（实测第一版暗部均色 `#7f450b`，色相 30°、饱和 84%，根本不是黑）。

跨度不够要**叠一块真实的光**，不是整体提亮。

### ⑤ 文字

字体与排版规则见下面第五节，逐行参数在 METHOD.md。

## 五、文字层：字体与"人味"

字体是这类海报的第二条命。必须是**细笔手写体**（不是毛笔、楷书、综艺体）：笔画细、有笔锋、单字不连笔、略右倾。

| 用途 | 用的 | 授权 |
|---|---|---|
| 中文手写 | 字制区 喜脉喜欢体（`fonts/xi-mail.ttf`） | 字制区系列一般标注免费商用，上线前核对授权页 |
| 英文手写 | Caveat（`fonts/caveat-400.woff2`） | SIL OFL，商用自由 |
| 备选中文 | 演示夏行楷 / 也字工厂小石头 / 沐瑶软笔手写体 | 逐个看授权 |
| 小字标签 | Cormorant Garamond | OFL |

**排版铁律：一行一个元素，每行独立设 字号 / 字距 / x / y / 旋转角。**

```
✗ 一个 text 块，统一字号、统一字距、左对齐  → 立刻像 PPT
✓ 字号差 3%~10%，正负字距混用，旋转角各不相同
```

另外两条：
- 中文用**暖白**不纯白（`#f2fcfd`、`#fef4d8`），加 `text-shadow` 或 `-webkit-text-stroke:.45px`，细笔画在花底上才不碎
- 英文用**撞色**，但只能一个；底图本身已多色时（霓虹类）改用**无彩强调**（奶白）

## 七、工作台

> 改文案、试版式、导出成品，不用再手改 HTML 坐标。

```bash
python3 workbench/serve.py        # 自动打开 http://127.0.0.1:8765/
```

**能改什么**：中文文案（一行一句，行数不限）、英文文案、刊头、落款、**字号倍率**、**字距**、文字色、撞色、**底图文件夹**、拉丝角度/长度、预饱和、取景上下、饱和/对比/明度。配置存 localStorage，刷新不丢。

**换底图**：底图那一栏填**任意文件夹路径**（支持 `~`，相对路径按仓库根目录解析），点「载入」或回车，下拉框立刻列出该文件夹里的所有图片（`.png/.jpg/.jpeg/.webp/.gif/.avif/.bmp`，不递归、跳过隐藏文件）。比如：

```
assets                                        # 内置 23 张
~/Pictures                                    # 自己的素材库
/Users/cass/Desktop                           # 桌面临时挑图
```

扫描上限 500 张，防止误选了巨大目录把下拉框卡死。

实现上预览和导出走**两条不同的路**，这点很关键：

| | 图片地址 | 原因 |
|---|---|---|
| 预览 | `/bg?path=<编码后的绝对路径>` | iframe 走 HTTP，服务端回传文件流 |
| 导出 | `file:///绝对/路径.jpg` | 导出是落成本地 HTML 再让 Chrome 截图，碰不到 HTTP 服务 |

所以两边都能拿到同一张图，不会出现"预览有图、导出来是空底"。

**字号**：滑杆是**倍率**（0.55×~1.6×），乘在自动排版结果上。面板底部实时显示「基准 xx px · 最宽一行 xx px」。倍率调到出画时，会**自动收窄到画幅上限**并提示「已自动收窄到 x.xx×」——因为手写体的实际字宽不是 1em，靠公式估算仍会轻微出画，所以用 `getBoundingClientRect` **实测 DOM 包围盒**再定倍率（最多重试 3 次防死循环）。导出用的是收窄后的倍率，保证预览和成品一致。

**6 种版式**（用同一套文案自动重排，不用手调坐标）：

| 版式 | 行为 | 适合 |
|---|---|---|
| 居中递变 | 字号逐行变化 + 居中 | 3~4 句，要节奏 |
| 竖排右起 | 一句一列，从右往左，英文在最左也竖排 | 3~5 列，每列 ≤7 字 |
| 巨句 | 首句压满宽度 + 通栏线 + 副句 | 首句 ≤5 字 |
| 居中等大 | 统一字号 + 垂直居中 | 5~8 句 |
| 沉底等大 | 统一字号 + 沉到底部 + 通栏线 + 左下刊头 | 5~10 句，画面优先 |
| 歌词居中 | 统一字号 + **整块水平垂直居中** + 署名跟到末行右下，**不排英文** | 歌词/诗，6~8 句 |

**参数表**：面板里所有滑杆（字号倍率/字距/拉丝角度/长度/预饱和/取景/饱和/对比/明度）由代码顶部一张 `SLIDERS` 表驱动，默认值、面板 HTML、回填、事件绑定都从它生成。加一个滑杆 = 表里加一行 + `buildHTML` 里读 `cfg.xxx`，不用再改四处。

**字距**是 em 单位（-0.05~0.40）。注意它和字号是**联动**的：块宽固定，字距调大 → 自动排版会把字号缩小来让位。实测（《山丘》6 行）字距 0.05/0.20/0.40 对应字号 53.9/47.5/41.1px、行距 80.8/71.3/61.7px，字间空隙扩大约 6 倍而整块宽度基本不变（676→702px），所以永远不会挤出画幅。

**歌词居中**这条是从《山丘》那张反推固定下来的，两个细节值得记：
- 居中按**墨迹**算，不按行盒：末行只占一个字高，行距多出来的空白不该算进块高，否则整块会偏上十几个像素。
- 居中后文字常常正压画面亮部，光晕要在 `.cn` 上单独加重一档，不然白字糊在亮背景里读不出来。选这个版式时英文输入框会自动禁用并标注「此版式不排英文」。

**自动字号**：宽度和高度双重约束取小值——`byW = 可用宽 / 最长行 em 数`，`byH = 可用高 / (行数 × 行高)`，再夹到 26~132px。所以加句子会自动缩，不会冲出画幅。

**导出**：点「导出 @2x PNG」→ 前端把整份海报 HTML POST 到 `/render` → 服务端落临时文件、调 Chrome headless 截图、回传 PNG 并下载。预览和导出**共用同一份 HTML**（预览加 `<base href="/">`，导出落到仓库根目录走相对路径），不会出现"预览是一回事、导出来是另一回事"。

**直链**：`http://127.0.0.1:8765/?layout=bottom` 可以直接进某个版式，方便分享和逐版验收。

**两个已知约束**：
- 78px 是 10 字行的上限，再长的句子会自动缩字号，但缩到 50px 以下手写体就糊了——文案该拆行。
- 竖排版式每列超过 7 字会顶到画框（字号被高度约束压小后又会显得空）。

## 九、坑

**全部 27 条在 [METHOD.md 第七节](METHOD.md)**，这里只留最贵的五条：

1. **底图只有一种材质**（满屏花/满屏叶）→ 糊完一块色斑，跨度再高也丑。先保证有景。
2. **在底图上量跨度** → 假象。底图 74~98，糊完只剩 19。**必须在成品上量**。
3. **用 brightness 救暗部** → 黑变棕，"黑金"变"棕金"。
4. **底图多色时还用撞色** → 没有环上剩下的色相了，改用奶白。
5. **别指望量化指标判断"丑不丑"**：我试过行内离散度、细节密度、极值面积占比，**三个都无法区分好坏**。这类问题目前只能靠肉眼和对图。
